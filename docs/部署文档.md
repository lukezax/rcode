## 1. 部署架构

```
                        ┌──────────────────────────┐
   用户浏览器  ───────▶  │  Nginx (80 / 443)         │
                        │  ├─ /            → 用户端 dist
                        │  ├─ /admin/      → 管理后台 dist
                        │  └─ /api/        → 反代 127.0.0.1:3000
                        └──────────────┬───────────┘
                                       │
                                       ▼
                        ┌──────────────────────────┐
                        │  NestJS (PM2, :3000)      │
                        │  SQLite: backend/data/... │
                        └──────────────────────────┘
```

- **Nginx**：静态资源托管 + API 反向代理 + HTTPS 终止；
- **PM2**：守护 NestJS 进程，支持开机自启与日志管理；
- **SQLite**：数据保存在 `backend/data/ai_referral_platform.db` 单文件。

> 本文以 Ubuntu 22.04 为例，示例域名 `example.com`，请替换为实际值。

## 2. 服务器与环境准备

### 2.1 服务器要求


```bash
sudo apt-get install -y nginx
sudo npm install -g pm2
```

```bash
sudo mkdir -p /var/www && cd /var/www
git clone git@github.com:lukezax/rcode.git
cd rcode
```

> 若无 SSH key，可改用 HTTPS 地址克隆。

## 3. 后端部署

### 3.1 安装依赖并构建

```bash
cd /var/www/rcode/backend
npm ci
npm run build
```

### 3.2 配置环境变量

```bash
cp .env.example .env
vi .env
```

生产环境 `.env` 示例：

```env
# 数据库（SQLite 文件路径）
DB_DATABASE=data/ai_referral_platform.db

# JWT（务必改成随机强密钥）
JWT_SECRET=请替换为足够长的随机字符串
JWT_EXPIRES_IN=7d

# 应用
PORT=3000
NODE_ENV=production

# 文件上传
UPLOAD_DIR=./uploads
MAX_FILE_SIZE=5242880
```

生成随机密钥：

```bash
openssl rand -hex 32
```

> ⚠️ 生产环境 `NODE_ENV=production` 时 `synchronize` 自动关闭（见 `database.config.ts`）。首次部署若表未创建，可临时以 `development` 启动一次完成建表与初始化，再切回 `production`；或后续启用 TypeORM migration。

### 3.3 首次初始化

首次启动会自动：

- 创建数据库表；
- 创建默认管理员 `admin@example.com` / `admin123`；
- 写入 20 个预置目标。

> ⚠️ **登录后台后请立即修改管理员密码。**

### 3.4 用 PM2 启动

```bash
cd /var/www/rcode/backend
pm2 start dist/main.js --name rcode-backend

# 查看状态与日志
pm2 status
pm2 logs rcode-backend
```

验证后端：

```bash
curl http://127.0.0.1:3000/api/targets
# 应返回 {"code":0,"message":"success",...}
```

## 4. 前端构建与托管

用户端与管理后台为纯静态 SPA，构建后由 Nginx 托管。

### 4.1 构建用户端

```bash
cd /var/www/rcode/frontend
npm ci
# 生产环境 API 地址（同域走 /api，无需写死端口）
echo "VITE_API_BASE_URL=/api" > .env.production
npm run build
# 产物：frontend/dist
```

### 4.2 构建管理后台

```bash
cd /var/www/rcode/admin
npm ci
echo "VITE_API_BASE_URL=/api" > .env.production
npm run build
# 产物：admin/dist
```

> 使用同域相对路径 `/api` 可避免 CORS，并由 Nginx 统一转发。

## 5. Nginx 配置

新建站点配置 `/etc/nginx/sites-available/rcode`：

```nginx
server {
    listen 80;
    server_name example.com;

    # 用户端静态资源
    root /var/www/rcode/frontend/dist;
    index index.html;

    # SPA history 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 管理后台（子路径 /admin/）
    location /admin/ {
        alias /var/www/rcode/admin/dist/;
        try_files $uri $uri/ /admin/index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, max-age=604800";
    }
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/rcode /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

> 若管理后台部署在**独立子域名**（如 `admin.example.com`），把 `location /admin/` 改为独立的 `server` 块、`root` 指向 admin/dist 即可。

### 5.1 关于管理后台的 history 路由

管理后台使用 `BrowserRouter`，直接访问 `/admin/targets` 等路径时需回退到 `/admin/index.html`（上面的 `try_files` 已处理）。

## 6. HTTPS 配置

使用 Let's Encrypt 免费证书（Certbot）：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d example.com
```

Certbot 会自动改写 Nginx 配置并开启 443。自动续期由系统定时任务处理，可验证：

```bash
sudo certbot renew --dry-run
```

## 8. 日志与监控

| 类型 | 位置 / 命令 |
|------|-------------|
| 后端应用日志 | `pm2 logs rcode-backend` / `~/.pm2/logs/` |
| Nginx 访问日志 | `/var/log/nginx/access.log` |
| Nginx 错误日志 | `/var/log/nginx/error.log` |
| 接口文档 | `https://example.com/api-docs` |

建议：

- 使用 `pm2-logrotate` 切割日志，避免磁盘占满：

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 10M
pm2 set pm2-logrotate:retain 7
```

- 配置 Uptime 监控（如 UptimeRobot）探测 `https://example.com/api/targets`。

## 9. 数据备份与恢复

### 9.1 备份

数据全部在 SQLite 单文件中，直接复制即可：

```bash
# 备份目录
mkdir -p /var/backups/rcode
cp /var/www/rcode/backend/data/ai_referral_platform.db \
   /var/backups/rcode/rcode-$(date +%F-%H%M).db
```

建议加入 crontab 每日备份并保留 7 天：

```bash
crontab -e
# 每天凌晨 3 点备份
0 3 * * * cp /var/www/rcode/backend/data/ai_referral_platform.db /var/backups/rcode/rcode-$(date +\%F).db && find /var/backups/rcode -name "rcode-*.db" -mtime +7 -delete
```

### 9.2 恢复

```bash
pm2 stop rcode-backend
cp /var/backups/rcode/rcode-2026-09-21.db \
   /var/www/rcode/backend/data/ai_referral_platform.db
pm2 start rcode-backend
```

> 恢复前请先停止后端进程，避免写入冲突。

## 11. 安全加固清单

部署上线前请逐项确认：

- [ ] 修改默认管理员密码（`admin@example.com` / `admin123`）
- [ ] `.env` 中 `JWT_SECRET` 使用随机强密钥
- [ ] `NODE_ENV=production`（关闭数据库自动同步）
- [ ] 配置 HTTPS，HTTP 自动跳转 443
- [ ] 防火墙仅放行 22 / 80 / 443（云服务器安全组同理）
- [ ] 数据库文件权限收敛（仅运行用户可读写）
- [ ] 配置数据库每日备份
- [ ] 关闭不必要的服务与端口
- [ ] 定期更新依赖与系统补丁

防火墙示例（ufw）：

```bash
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable
```

## 12. 常见问题

**Q1：后端启动报 `ENOENT: no such file or directory, open 'data/...db'`**
A：`database.config.ts` 已自动创建父目录。若仍报错，确认运行用户对 `backend/data` 有写权限。

**Q2：前端页面刷新 404**
A：Nginx 未配置 SPA 回退。确认 `try_files $uri $uri/ /index.html;`（管理后台为 `/admin/index.html`）。

**Q3：接口跨域 / CORS 报错**
A：生产环境前端应使用相对路径 `/api`，由 Nginx 同域转发，避免跨域。

**Q4：管理后台登录后立刻被登出**
A：多为 `JWT_SECRET` 变更或 token 过期，重新登录即可；确认前后端使用同一域名。

**Q5：如何查看接口是否正常？**
A：`curl https://example.com/api/targets`，返回 `{"code":0,...}` 即正常。

**Q6：想迁移到 PostgreSQL / MySQL 怎么办？**
A：修改 `src/config/database.config.ts` 的 `type` 与连接参数，安装对应驱动，并将 `synchronize` 交给 migration 管理即可。当前表结构为通用关系模型，迁移成本较低。
