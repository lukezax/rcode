## 2. 产品定位与目标

### 2.1 产品定位

一个专注于 AI 工具邀请码分享的平台，解决以下痛点：
- 邀请码信息分散，难以找到
- 失效邀请码多，浪费时间
- 分享者和使用者之间缺乏可信渠道
- 缺乏有效性反馈机制

### 2.2 MVP 核心目标

**验证核心闭环**：
1. 用户能否顺利找到目标工具并查看邀请码
2. 邀请码详情页的复制率
3. 有效/无效反馈数量
4. 用户上传邀请码的数量与通过率
5. 目标新增申请的审批通过率

**成功指标**：
- DAU（日活跃用户）：100+
- 邀请码上传量：50+/周
- 有效反馈率：30%+
- 邀请码复制率：20%+

## 3. 用户角色分析

### 3.1 游客（未登录用户）

**特征**：
- 首次访问，对平台不熟悉
- 想快速查看某个 AI 工具的邀请码
- 不想注册，只想浏览

**需求**：
- 浏览目标列表
- 查看邀请码列表（部分信息）
- 查看邀请码详情（部分信息）
- 被引导注册/登录

**限制**：
- 不能查看完整邀请码
- 不能复制邀请码
- 不能上传邀请码
- 不能反馈有效性
- 不能申请新增目标

### 3.2 登录用户

**特征**：
- 已注册，有邮箱账号
- 可能是分享者（上传邀请码）
- 可能是使用者（查找邀请码）
- 可能两者都是

**需求**：
- 查看完整邀请码
- 复制邀请码
- 反馈有效性
- 上传邀请码
- 申请新增目标
- 查看自己的上传记录
- 查看自己的反馈记录

**限制**：
- 同一目标每日最多上传 3 条邀请码
- 同一邀请码不能重复上传
- 不能给自己的邀请码投票
- 同一邀请码只能投票一次

### 3.3 管理员

**特征**：
- 平台运营人员
- 负责内容审核和管理
- 关注平台数据

**需求**：
- 审批新增目标申请
- 管理邀请码（查看、搜索、下架）
- 处理举报
- 管理用户（查看、封禁）
- 查看数据看板

**权限**：
- 所有数据的查看权限
- 目标审批权限
- 邀请码下架权限
- 用户封禁权限

### 4.2 首页模块

#### 4.2.1 功能描述

首页是用户进入平台的第一页，需要快速展示核心内容，引导用户找到目标工具。

#### 4.2.2 功能点

| 功能点 | 说明 | 优先级 |
|--------|------|--------|
| 搜索框 | 按工具名称搜索目标 | P0 |
| 分类导航 | 展示 AI 工具分类，点击筛选 | P0 |
| 热门目标 | 按邀请码数量/查看量排序展示 | P0 |
| 最新邀请码 | 跨目标展示最新上传的邀请码 | P1 |
| 目标卡片 | 展示目标名称、Logo、邀请码数量 | P0 |

#### 4.2.3 业务规则

1. **搜索规则**：
   - 支持模糊搜索
   - 搜索范围：目标名称、英文名
   - 实时搜索（输入即搜索）或点击搜索按钮

2. **分类规则**：
   - 分类列表：AI 编程、AI 写作、AI 绘图、AI 视频、AI 音频、AI 搜索、AI 办公、AI Agent
   - 点击分类后，展示该分类下的所有目标
   - 支持多选分类（P1）

3. **排序规则**：
   - 热门目标：按邀请码数量降序，邀请码数量相同时按查看量降序
   - 最新邀请码：按创建时间降序

4. **分页规则**：
   - 目标列表：每页 20 条
   - 邀请码列表：每页 20 条

### 4.3 目标模块

#### 4.3.1 功能描述

目标模块包括目标详情页、申请新增目标页。

#### 4.3.2 功能点

| 功能点 | 说明 | 优先级 |
|--------|------|--------|
| 目标详情页 | 展示目标信息和邀请码列表 | P0 |
| 申请新增目标 | 用户提交新目标申请 | P0 |
| 目标信息展示 | 名称、Logo、简介、官网、分类 | P0 |

#### 4.3.3 业务规则

1. **目标状态**：
   - `pending`：待审批（用户申请的新目标）
   - `active`：已启用（预置或审批通过）
   - `rejected`：已拒绝（审批拒绝）
   - `disabled`：已停用（管理员停用）

2. **目标可见性**：
   - 游客和登录用户只能看到 `active` 状态的目标
   - 管理员可以看到所有状态的目标

3. **申请规则**：
   - 必须登录
   - 同名目标不能重复申请
   - 提交后状态为 `pending`
   - 管理员审批通过后变为 `active`

4. **邀请码列表排序**：
   - 默认：有效票优先 + 最新
   - 可切换：最新、最多查看、最多有效

#### 4.3.4 用户故事

```

验收标准：
- 顶部展示目标信息：Logo、名称、分类、简介、官网链接
- 中部展示邀请码列表
- 底部有"上传邀请码"按钮（登录后可见）
- 支持排序切换
- 支持分页加载
```

```

验收标准：
```

### 4.4 邀请码模块

#### 4.4.1 功能描述

邀请码模块包括邀请码列表、邀请码详情、上传邀请码、有效性反馈。

#### 4.4.2 功能点

| 功能点 | 说明 | 优先级 |
|--------|------|--------|
| 邀请码列表 | 在目标详情页展示邀请码列表 | P0 |
| 邀请码详情 | 展示完整邀请码、复制、反馈 | P0 |
| 上传邀请码 | 登录用户上传邀请码 | P0 |
| 有效性反馈 | 用户投票标记有效/无效 | P0 |
| 举报 | 举报违规邀请码 | P1 |

#### 4.4.3 业务规则

1. **邀请码状态**：

| 状态 | 条件 | 说明 |
|------|------|------|
| 待验证 | 总票数 = 0 或 有效票 = 无效票 | 默认状态 |
| 有效 | 有效票 > 无效票 | 社区验证有效 |
| 无效 | 无效票 > 有效票 | 社区验证无效 |
| 已过期 | 超过有效期 | 系统自动标记 |
| 已下架 | 管理员下架 | 违规或举报核实 |

2. **邀请码展示规则**：
   - 列表页：邀请码部分隐藏，如 `ABC***XYZ`
   - 详情页：游客看到部分隐藏，登录用户看到完整邀请码

3. **上传限制**：
   - 同一用户对同一目标每日最多上传 3 条
   - 同一邀请码不能重复上传（全局唯一）
   - 必须选择已启用的目标

4. **反馈规则**：
   - 必须登录
   - 同一用户对同一邀请码只能投票一次
   - 可修改投票
   - 上传者不能给自己的邀请码投票
   - 投票后实时更新状态

5. **防刷规则**：
   - 同一 IP 对同一邀请码限制投票频率（1 分钟内只能投 1 次）
   - 同一设备 ID 限制（P1）

### 4.6 认证模块

#### 4.6.1 功能描述

认证模块包括注册、登录、找回密码。

#### 4.6.2 功能点

| 功能点 | 说明 | 优先级 |
|--------|------|--------|
| 注册 | 邮箱 + 密码注册 | P0 |
| 登录 | 邮箱 + 密码登录 | P0 |
| 找回密码 | 邮箱验证码重置密码 | P1 |
| 退出登录 | 退出当前账号 | P0 |

#### 4.6.3 业务规则

1. **注册规则**：
   - 邮箱格式验证
   - 密码强度：至少 8 位，包含字母和数字
   - 邮箱唯一性校验
   - 可选：邮箱验证码验证

2. **登录规则**：
   - 邮箱 + 密码登录
   - 登录失败提示：邮箱或密码错误
   - 连续失败 5 次后，锁定 15 分钟（P1）

3. **会话管理**：
   - 使用 JWT Token
   - Token 有效期：7 天
   - 支持自动续期

## 8. 风险与建议

### 8.1 风险识别

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 邀请码失效快 | 用户体验差 | 详情页显著提示有效期，鼓励反馈 |
| 垃圾上传 | 内容质量低 | 限制每日上传数，增加举报机制 |
| 目标审批积压 | 用户等待时间长 | 支持批量审批，设置审批提醒 |
| 冷启动内容少 | 用户留存低 | 运营团队预上传真实邀请码 |
| 合规风险 | 法律问题 | 明确免责声明，不参与交易 |

### 8.2 建议

1. **运营建议**：
   - 上线前预置 20+ 主流 AI 工具
   - 运营团队预上传 50+ 真实邀请码
   - 建立用户反馈渠道（微信群/公众号）

2. **产品建议**：
   - MVP 阶段聚焦核心闭环，不追求完美
   - 快速上线，根据数据迭代
   - 关注用户反馈，及时调整

3. **技术建议**：
   - 代码结构清晰，便于后续扩展
   - API 设计规范，便于小程序复用
   - 数据库设计考虑扩展性
