## 1. 产品简介

AI 邀请码分享平台用于集中展示和交换各类 AI 工具的邀请码/推荐码，解决邀请码信息分散、失效码多、缺乏可信交换渠道的问题。

核心能力：

- **按工具分类浏览**：首页按分类和关键词查找 AI 工具；
- **邀请码分享**：登录用户上传自己的邀请码，获得曝光；
- **有效性反馈**：使用者投票「有效 / 无效」，社区共同筛选真实可用的码；
- **内容治理**：用户可举报，管理员审批目标、下架违规内容。

系统由三部分组成：

| 部分 | 说明 | 默认地址 |
|------|------|----------|
| 用户端 Web | 面向普通用户 | http://localhost:5173 |
| 管理后台 | 面向平台管理员 | http://localhost:5174 |
| 后端服务 | 提供 API 与数据存储 | http://localhost:3000 |

## 2. 角色与权限

| 角色 | 说明 | 可以做什么 |
|------|------|-----------|
| **游客** | 未登录用户 | 浏览目标与邀请码列表、查看详情页的部分信息 |
| **登录用户** | 注册/登录后的用户 | 查看完整邀请码、复制、反馈有效/无效、上传邀请码、申请新增目标、查看个人中心 |
| **管理员** | 平台运营人员 | 目标审批、邀请码管理、举报处理、用户管理、查看数据看板 |

**游客与登录用户的差异**：

| 能力 | 游客 | 登录用户 |
|------|:----:|:--------:|
| 浏览首页/目标列表 | ✅ | ✅ |
| 查看邀请码列表（部分隐藏，如 `ABC***XYZ`） | ✅ | ✅ |
| 查看邀请码详情页 | ✅（邀请码隐藏） | ✅（完整邀请码） |
| 复制邀请码 | ❌ | ✅ |
| 反馈有效/无效 | ❌ | ✅ |
| 上传邀请码 | ❌ | ✅ |
| 申请新增目标 | ❌ | ✅ |
| 举报邀请码 | ❌ | ✅ |

## 3. 环境准备与启动

### 3.1 环境要求

- Node.js 20 及以上
- npm（随 Node.js 安装）
- 无需安装任何数据库（使用 SQLite，数据保存在本地文件中）

### 3.2 启动后端服务

```bash
cd backend
npm install
cp .env.example .env      # 可选：修改端口、JWT 密钥
npm run start:dev
```

启动成功后：

- 服务地址：http://localhost:3000
- 接口文档（Swagger）：http://localhost:3000/api-docs

首次启动会自动完成：

1. 创建数据库表；
2. 创建默认管理员账号；
3. 写入 20 个预置 AI 工具。

**默认管理员账号**：

```
邮箱：admin@example.com
密码：admin123
```

> ⚠️ 正式环境请务必修改默认管理员密码和 `.env` 中的 `JWT_SECRET`。

### 3.3 启动用户端

```bash
cd frontend
npm install
npm run dev
```

浏览器访问：http://localhost:5173

### 3.4 启动管理后台

```bash
cd admin
npm install
npm run dev
```

浏览器访问：http://localhost:5174

### 3.5 运行端到端测试

确保后端已启动后，在项目根目录执行：

```bash
bash backend/scripts/e2e-test.sh
```

脚本会依次测试认证、目标、邀请码、反馈、举报、用户中心、管理后台等接口，最后输出通过/失败数量。

### 3.6 生产构建

```bash
# 用户端
cd frontend && npm run build      # 产物在 frontend/dist

# 管理后台
cd admin && npm run build         # 产物在 admin/dist

# 后端
cd backend && npm run build && npm run start:prod
```

## 4. 用户端使用说明

### 4.1 注册与登录

**注册**：

1. 点击右上角「注册」；
2. 填写邮箱、昵称（可选）、密码（至少 8 位）；
3. 提交后自动登录并跳转首页。

**登录**：

1. 点击右上角「登录」；
2. 输入注册时的邮箱和密码；
3. 登录成功后可查看完整邀请码、上传、反馈等。

> 登录状态保存在浏览器本地，关闭浏览器后再次打开仍然保持登录（有效期 7 天）。

### 4.2 浏览与搜索工具

**首页**提供三种查找方式：

1. **搜索框**：输入工具名称（如 `Cursor`），回车或点击「搜索」；
2. **分类标签**：点击「AI 编程 / AI 写作 / AI 绘图 / AI 视频 / AI 音频 / AI 搜索 / AI 办公 / AI Agent」筛选；再次点击同一分类可取消筛选；
3. **工具卡片**：点击卡片进入该工具的详情页。

### 4.3 查看某工具的邀请码

1. 在首页点击任意工具卡片，进入**目标详情页**；
2. 页面顶部展示工具名称、分类、简介、官网；
3. 中部是邀请码列表，每条显示：隐藏的邀请码、上传者、查看次数、有效/无效票数、状态标签、上传时间；
4. 右上角可切换排序方式：
   - 默认（有效优先）
   - 最新
   - 最多查看
   - 最多有效

### 4.4 查看邀请码详情与复制

1. 在列表点击「查看详情」或整行，进入**邀请码详情页**；
2. 详情页展示：邀请码、状态、上传者、上传时间、查看次数、有效/无效数量、有效期、分享者奖励、被分享者奖励、备注；
3. **游客**只能看到部分隐藏的邀请码（如 `INV***ABC`），并提示登录后可见；
4. **登录用户**可看到完整邀请码，点击「复制邀请码」即可复制到剪贴板；
5. 若有推荐链接，可点击「打开推荐链接」跳转。

> 每次进入详情页，查看次数会自动 +1。

### 4.5 反馈「有效 / 无效」

1. 在邀请码详情页底部，点击「我用过，有效」或「我用过，无效」；
2. 系统提示「感谢您的反馈」，票数和状态实时更新；
3. 同一用户对同一邀请码只能投一票，但可以随时改票（点击另一个按钮）；
4. 上传者不能给自己的邀请码投票。

状态规则：

| 条件 | 状态 |
|------|------|
| 有效票 > 无效票 | 有效 |
| 无效票 > 有效票 | 无效 |
| 票数相等或都为 0 | 待验证 |

### 4.6 上传邀请码

1. 登录后，点击顶部「上传邀请码」，或在目标详情页点击「上传该工具邀请码」；
2. 选择工具（只能选已启用的工具）；
3. 填写：
   - 邀请码/推荐码（必填）
   - 推荐链接（可选）
   - 分享者奖励说明（可选）
   - 被分享者奖励说明（可选）
   - 有效期（可选）
   - 备注（可选）
4. 提交后邀请码进入列表，状态为「待验证」。

**限制**：

- 同一邀请码不能重复上传；
- 同一用户对同一工具每日最多上传 3 条。

### 4.7 申请新增工具

1. 登录后进入申请页（可从个人中心或相关入口进入）；
2. 填写：工具名称、英文名/唯一标识（小写字母、数字、短横线）、分类、官网、Logo 链接、简介、申请理由；
3. 提交后状态为「待审批」；
4. 管理员审批通过后，该工具对所有用户可见，可开始上传邀请码；
5. 若被拒绝，可在个人中心看到拒绝原因。

> 同一名称或唯一标识的工具不能重复申请。

### 4.8 举报邀请码

1. 登录后在邀请码详情页底部点击「举报该邀请码」；
2. 选择原因（已失效 / 虚假信息 / 违规内容 / 其他），可填写详细说明；
3. 提交后提示「举报已提交」。同一用户对同一邀请码只能举报一次；
4. 管理员核实后可能下架该邀请码。

### 4.9 个人中心

点击顶部「我的」进入个人中心，包含三个标签页：

- **我的上传**：查看自己上传的邀请码及其状态、查看/有效/无效数量；
- **我的反馈**：查看自己投过的票及点评；
- **我的申请**：查看提交的工具申请及审批状态、拒绝原因。

## 5. 管理后台使用说明

访问 http://localhost:5174，使用管理员账号登录（默认 `admin@example.com` / `admin123`）。

> 非管理员账号无法登录后台。

### 5.1 数据看板

展示平台整体数据：

- 目标总数、邀请码总数、用户总数
- 待审批目标数、待处理举报数
- 有效邀请码数、无效邀请码数

### 5.2 目标审批

1. 进入「目标审批」，列表展示所有「待审批」的工具申请；
2. 点击「通过」：工具状态变为「已启用」，对所有用户可见；
3. 点击「拒绝」：填写拒绝原因后提交，申请人可在个人中心看到原因。

### 5.3 邀请码管理

1. 进入「邀请码管理」，可按关键词搜索邀请码、按状态筛选（待验证/有效/无效/已过期/已下架）；
2. 列表展示邀请码、所属工具、上传者、查看/有效/无效数量、状态；
3. 点击「下架」并确认后，邀请码状态变为「已下架」，不再出现在用户端列表中。

### 5.4 举报处理

1. 进入「举报处理」，默认展示「待处理」举报；
2. 可切换标签查看「已下架 / 已驳回 / 全部」；
3. 对每条举报可执行：
   - **核实后下架**：下架被举报的邀请码，举报状态变为「已下架」；
   - **驳回**：举报状态变为「已驳回」。

### 5.5 用户管理

1. 进入「用户管理」，列表展示所有用户及其角色、状态、注册时间；
2. 对普通用户可执行「封禁 / 解封」；
3. 管理员账号不可被封禁。

## 6. 业务规则说明

### 6.1 邀请码状态

| 状态 | 说明 |
|------|------|
| 待验证 | 默认状态，票数相等或都为 0 |
| 有效 | 有效票 > 无效票 |
| 无效 | 无效票 > 有效票 |
| 已过期 | 超过有效期（系统标记） |
| 已下架 | 管理员下架或举报核实后下架 |

### 6.2 防刷与限制

| 规则 | 说明 |
|------|------|
| 一票制 | 同一用户对同一邀请码只能投一票，可修改 |
| 禁止自投 | 上传者不能给自己的邀请码投票 |
| 上传频率 | 同一用户对同一工具每日最多上传 3 条 |
| 唯一性 | 同一邀请码全局不可重复上传 |
| 举报限制 | 同一用户对同一邀请码只能举报一次 |

### 6.3 内容可见性

- 游客：邀请码部分隐藏，推荐链接不可见；
- 登录用户：可见完整邀请码与推荐链接；
- 已下架邀请码：不出现在工具详情列表中。

## 7. 常见问题 FAQ

**Q1：为什么我看不到完整的邀请码？**
A：游客只能看到部分隐藏的邀请码。请先注册/登录后再查看。

**Q2：点击「复制邀请码」没有反应？**
A：复制功能需要浏览器剪贴板权限，请允许权限或使用 HTTPS 访问。若仍失败，可手动选中复制。

**Q3：我上传的邀请码为什么是「待验证」？**
A：「待验证」是默认状态。当其他用户使用后投票，有效票多于无效票时会自动变为「有效」。

**Q4：为什么我不能给自己的邀请码投票？**
A：为防止刷票，系统禁止上传者给自己的邀请码投票。

**Q5：同一邀请码为什么上传不了？**
A：系统对邀请码做了全局唯一校验，已存在的邀请码无法重复上传。

**Q6：上传提示「每日最多上传 3 条」怎么办？**
A：同一用户对同一工具每日上限为 3 条，请次日再上传，或换一个工具。

**Q7：申请新增工具后多久能通过？**
A：取决于管理员审批进度。可在「个人中心 → 我的申请」查看状态和拒绝原因。

**Q8：管理员忘记密码怎么办？**
A：可在后端数据库中重置，或重新初始化数据库（会清空数据，请谨慎）。

**Q9：数据存在哪里？会不会丢？**
A：数据保存在 `backend/data/ai_referral_platform.db` 文件中。备份该文件即可备份全部数据。

**Q10：前端页面打不开或接口报错？**
A：请确认后端服务已启动（http://localhost:3000 可访问），并检查前端 `.env` 中的 `VITE_API_BASE_URL` 是否正确指向后端地址。
